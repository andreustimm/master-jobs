# ADR-011: Term Captures Ingest Under a Non-Synced Source per Platform, Without Reassigning Jobs

## Status

Accepted

## Date

2026-09-18

## Context

`observeRawJob` (`src/core/ingest/observe.ts:91-183`) is the only ingestion
funnel. On update it writes `{...values, closedAt: null}` (`:168-171`), which
overwrites `sourceId`, `externalId` and `url` and does not clear `archivedAt`.
Closure by absence (`run.ts:115-127`) keys on `job.sourceId`, so the last
observer owns closure. Source ids are `kind:handle`, so a term used as a handle
would put the term text in every log that prints source ids. Network payloads
are discarded except `workplaceType` (ADR 0019), so platform tags are gone after
observation. PRD rules 21–22 require term captures to never close, archive or
reassign jobs, to reopen per ADR 0020 item 7, and to attribute jobs to terms
using title, company, description or platform tags.

## Decision

- Each budgeted platform gets one source row for term captures, id
  `<kind>:~terms` (label "<Platform> — termos"), created with `enabled: false`.
  `syncAll` reads `config/sources.yaml`, so it never syncs or closes this source;
  only verification (404/410) closes its jobs.
- `observeRawJob` gains an option `{ keepExistingSource: true }`: when the job
  already exists, the update leaves `sourceId`, `externalId`, `url` and
  `applyUrl` untouched and refreshes the remaining fields. New jobs take the
  `~terms` source.
- Reopening in `observeRawJob` clears `archivedAt` together with `closedAt`, as
  ADR 0020 item 7 already requires for every path; this fixes the regular sync
  too.
- `RawJob` gains `tags?: string[]`. Attribution is decided inside the capture,
  before observation discards the payload: `isAttributable(term, raw)` checks
  title, company, description and tags with the whole-word pattern of ADR-012;
  a hit writes `term_attribution(term_key, job_id)`.

## Alternatives Considered

### Alternative 1: One source per term

- **Description**: `remotive:laravel` as an ordinary source.
- **Pros**: Reuses `syncOne`.
- **Cons**: Closure by absence on a partial window; reassignment of existing
  jobs; term text in source ids and logs.
- **Why rejected**: Violates rules 21 and 47.

### Alternative 2: Persist full raw payloads for term captures

- **Description**: Keep the payload to decide attribution later.
- **Pros**: Attribution can be recomputed.
- **Cons**: Contradicts ADR 0019's retention rule.
- **Why rejected**: Deciding at capture time needs no retention.

## Consequences

### Positive

- A term capture cannot hide a job or change its lifecycle owner.
- Term text never enters a source id.

### Negative

- Jobs first seen through a term belong to `~terms` sources; the Jobs screen
  source filter lists them as "<Platform> — termos".

### Risks

- The reopen fix changes sync behavior for archived jobs that reappear; this is
  the documented intent of ADR 0020 item 7 and gets its own regression test.

## Implementation Notes

`ensureTermSource(kind)` upserts the `~terms` row on first use. The Zod schema
of `config/sources.yaml` (`src/core/sources/config.ts`) gains a refinement that
rejects handles starting with `~`, so a configured source can never take a
term-capture source id.
