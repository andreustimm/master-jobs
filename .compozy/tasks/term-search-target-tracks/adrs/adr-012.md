# ADR-012: One Whole-Word Term Pattern Builder for TypeScript and PostgreSQL

## Status

Accepted

## Date

2026-09-18

## Context

Four places match a term: the Jobs screen filter (SQL over up to 10,000 open
jobs), attribution at capture time (TypeScript), the accepted-track relevance
gate (TypeScript), and term equivalence when saving (TypeScript). PRD rule 12
treats case, spaces and hyphens inside a term as equivalent; rule 33 uses the
scorer's word boundary (anything other than a letter, digit, `+` or `#`
separates words). The scorer's `containsTerm` (`score.ts:113-116`) is
module-private; `src/core/db/work-mode.ts` uses a different SQL boundary that
treats `+` and `#` as separators; the skills matcher uses a third variant. No
text index or PostgreSQL extension exists.

## Decision

- A pure module `src/core/term.ts` owns term handling:
  - `termKey(term)`: lowercase, trim, remove spaces and hyphens
    (`Tech Lead` → `techlead`).
  - `validateTerm(term)`: PRD rule 11.
  - `termPattern(term)`: the regex body. Each character of the key is escaped,
    and an optional `[ -]?` separator sits between consecutive letters or
    digits, so `techlead` matches `tech lead`, `tech-lead` and `techlead`.
    The body is wrapped with the scorer's boundary:
    `(^|[^a-z0-9+#])<body>([^a-z0-9+#]|$)`.
  - `matchesTerm(term, text)` in TypeScript, and `termRegexSql(term)`, which
    returns the same string for PostgreSQL `~*`.
- The Jobs screen filter applies `~*` to `lower(title)`, `lower(company_name)`
  and `lower(coalesce(job_page.text, job.description_text))`, and adds no index
  now. The hybrid-search PRD owns trigram indexing and adds it without changing
  which jobs match.
- `scoreJob` keeps its own `containsTerm`; the boundary class is exported from
  `src/core/term.ts` and imported by `score.ts`, so both use one constant.

## Alternatives Considered

### Alternative 1: `pg_trgm` GIN index now

- **Description**: Enable the extension and index the searchable text.
- **Pros**: Faster regex at larger scale.
- **Cons**: Overlaps the hybrid-search PRD's ownership; a new extension on the
  production database for a corpus of about 6,000 open jobs.
- **Why rejected**: Measured need first; the integration test bounds the query.

### Alternative 2: Full-text search (`tsvector`)

- **Description**: `websearch_to_tsquery`.
- **Pros**: Indexable, ranked.
- **Cons**: Stemming changes the result set and the parser drops `#` and `+`
  (`C#` becomes `c`).
- **Why rejected**: Breaks rule 12 and US-021 EC-2.

## Consequences

### Positive

- One definition of "whole word" across filter, attribution and relevance.
- `C#`, `C++`, `.NET` and `Node.js` match literally.

### Negative

- Optional separators between every letter also accept rare spellings such as
  `ja va`; accepted as noise.

### Risks

- Regex over descriptions may exceed 2 seconds as the corpus grows; the
  integration test at 10,000 jobs guards the target, and the hybrid-search
  trigram index is the remedy.

## Implementation Notes

The SQL string is passed as a bound parameter, never interpolated.
