# ADR-004: Access has no end by default, takes an optional end date, and ends immediately on revocation or expiry

## Status

Accepted

## Date

2026-10-06

## Context

LGPD art. 8 and GDPR art. 7 require that consent can be withdrawn at any time,
as easily as it was given, with effect from that moment forward. Drive lets the
sharer set an expiration per person. The session already reloads
`linkedCandidateIds` on every request, so a removed link takes effect on the
recruiter's next request. Today revocation deletes the row, which erases who
granted what and when.

Decided by the owner on 2026-10-06.

## Decision

- A grant has no end by default. When granting (or later, while active), the
  candidate may set an optional end date, which must be in the future.
- At the end of the end date (end of day in the candidate's time zone, see PRD),
  access ends exactly as in a revocation.
- Revocation is one action on the same page where access was granted and takes
  effect on the recruiter's next request.
- Ending access is forward-only: what the recruiter already saw is not
  recalled; suggestions already made stay with the candidate (ADR-003).
- An ended grant is kept as a historical record (who, to whom, when, how it
  ended), not deleted.

## Alternatives Considered

### Alternative 1: Mandatory expiry (e.g. 90 days)

- **Description**: Every grant expires and must be renewed.
- **Pros**: Forgotten grants close themselves.
- **Cons**: Interrupts long engagements; the owner prefers opt-in expiry.
- **Why rejected**: Owner decision.

### Alternative 2: Keep deleting the row on revocation

- **Description**: Revocation removes the link with no trace.
- **Pros**: Simple.
- **Cons**: Loses the consent record LGPD expects.
- **Why rejected**: History is required (ADR-005).

## Consequences

### Positive

- Withdrawal is as easy as consent and immediate.

### Negative

- Expiry needs a time reference and a check at request time, not only a
  background job.

### Risks

- Expiry evaluated only by a background job would leave a window of access;
  the check must hold at request time.

## Implementation Notes

The link table gains lifecycle data or a companion grant record; only active,
unexpired grants enter `linkedCandidateIds`.
