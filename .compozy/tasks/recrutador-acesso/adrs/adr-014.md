# ADR-014: The CV second consent applies to Recruiters and Public

## Status

Accepted

## Date

2026-10-06

## Context

Decided by the owner on 2026-10-06.

`setVisibilityAction` (`app/candidate/actions.ts`) stores `public_cv = true`
only when the visibility is `public` and the box is checked, so leaving Public
always clears the consent. With the directory (ADR-010, ADR-013), a profile set
to Recruiters is read by authenticated recruiters, and the question is whether
it may show the CV text.

## Decision

- The second consent (`public_cv`) is offered and kept for **Recruiters** and
  **Public**. Moving to Private clears it; moving between Recruiters and
  Public keeps the value submitted with the form.
- Wherever the CV text appears outside a grant — `/p/[slug]` and the
  directory — it passes through `publicCvMarkdown()`, which applies
  `publicCvText()`. The raw CV is shown only on the grant page (ADR-002).
- `setVisibilityAction` also requires `access:manage`, so a borrowed session
  cannot change visibility or the consent (US-028.EC-4).

## Alternatives Considered

### Alternative 1: CV only for Public

- **Pros**: Smaller exposure for Recruiters profiles.
- **Cons**: Recruiters profiles would lose the most useful field for discovery.
- **Why rejected**: Owner decision.

### Alternative 2: Separate consent per visibility

- **Pros**: Finer control.
- **Cons**: Two checkboxes for one question.
- **Why rejected**: One consent, explained per option.

## Consequences

### Positive

- Recruiters visibility becomes useful without going public.

### Negative

- Candidates who return from Public to Recruiters keep the consent only if they
  leave the box checked.

### Risks

- A filter miss in `publicCvText()` now reaches self-signed-up recruiters too;
  the filter is unchanged and covered by its existing suite.

## Implementation Notes

The visibility hints in `src/core/i18n/` change for Recruiters (reach includes
self-signed-up recruiters) and the consent label names both visibilities.
