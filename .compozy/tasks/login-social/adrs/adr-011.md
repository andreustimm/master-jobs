# ADR-011: Localized account emails over the existing Mailer, with a file sink outside production

## Status

Accepted

## Date

2026-10-06

## Context

The `Mailer` port and its adapters (Resend, console, withheld) already exist; `configuredMailer(env)` picks Resend when `RESEND_API_KEY` and `RESEND_FROM` are set, console for local without a key, and withheld otherwise (Preview). Only the password-recovery email exists, with fixed Portuguese text. The new emails (code, welcome, provider notices, account-exists, recovery) need both languages, and tests must read the sign-up code. Codes must never appear in deployment logs.

## Decision

- Message builders live in `src/contexts/auth/app/account-emails.ts`, one pure function per message, taking the locale and returning `{ subject, text }`; strings come from the i18n dictionary (`email.*` keys).
- New adapter `fileMailer` writes each message as a JSON file under `JHO_MAIL_SINK`, accepted only when `JHO_ENV` is not `production`. E2E sets it and reads the code from the file.
- Preview keeps the withheld mailer; manual sign-up is unavailable there with a message (social sign-in is already unavailable, ADR-005). Password sign-in keeps working.
- Sender stays `RESEND_FROM` = `contato@mastertimm.com.br`.
- A delivery failure records `email_send_failed` with the message kind; it blocks nothing except the code step, which offers resend.

## Alternatives Considered

### Alternative 1: Preview sends to an allowlist

- **Description**: Real emails to listed recipients.
- **Pros**: Manual sign-up testable in Preview.
- **Cons**: Extra configuration and risk of real sends.
- **Why rejected**: Owner chose unavailable-in-Preview.

### Alternative 2: Log codes in Preview

- **Description**: Print codes to logs.
- **Pros**: Simple.
- **Cons**: Violates "never log codes in deployments".
- **Why rejected**: Unsafe.

## Consequences

### Positive

- One channel, localized, testable end to end.

### Negative

- Manual sign-up cannot be exercised in Preview.

### Risks

- Misconfigured `JHO_MAIL_SINK` in production: ignored by environment check.

## Implementation Notes

The recovery email moves to the localized builder; its behavior (G17/G18) stays.
