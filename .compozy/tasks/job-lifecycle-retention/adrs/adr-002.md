# ADR-002 — Query-based scoped history before counters

**Status:** Accepted  
**Date:** 2026-09-16

## Decision

Build candidate and recruiter summaries from `application` and
`application_event` queries with authorization applied before aggregation. Add
materialized counters only after measured query pressure justifies them.

## Alternatives Considered

- Increment counters on every transition: rejected because drift would make
  the durable event log and UI disagree.
- Read globally then filter in memory: rejected because it risks cross-candidate
  disclosure.

## Consequences

The first implementation is easy to rebuild and audit. It requires suitable
indexes and pagination; those are measured rather than guessed.
