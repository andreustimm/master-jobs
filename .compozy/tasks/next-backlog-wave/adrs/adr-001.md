# ADR-001: Candidate-scoped rescore status read model

- **Status:** Accepted
- **Date:** 2026-08-25

## Context

The score queue already exists and is keyed by candidate, but the candidate page
does not expose its state. A global count would leak another candidate's queue
state and would not tell the signed-in user whether their own CV is being
processed.

## Decision

Expose a candidate-scoped status query from the existing scoring queue module.
The page will obtain the current candidate id from the session guard and render
localized status counts using the existing design tokens and feedback patterns.

## Alternatives considered

- Query `score_task` directly in JSX: rejected because UI pages are adapters and
  shared queries belong behind a public core API.
- Return a global status map: rejected because queue state is candidate data.
- Add polling or a broker: rejected; the first release only needs an accurate
  read on navigation and refresh, and the project deliberately uses a database
  queue.

## Consequences

The queue module gains a small read model and its unit tests must prove candidate
isolation. The UI remains server-rendered, localized, and responsive without a
new client-side dependency.
