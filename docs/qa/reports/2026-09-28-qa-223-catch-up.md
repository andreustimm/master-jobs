## Learnings

- **O banco de dev local compartilhado (`master-jobs-local-supabase-db`,
  porta 5433) estava 24 migrations atrás de `dev`** (só 4 de 28 aplicadas,
  datadas de 09-09 a 09-18) e travava `/jobs` inteiro com `Failed query`
  assim que a sessão começou. `pnpm db:migrate` falhava sem mostrar a causa
  (spinner do `drizzle-kit` engole o erro, o mesmo padrão do `rtk` já
  registrado em memória); a causa real só apareceu chamando
  `drizzle-orm/postgres-js/migrator` direto: duas contas de teste
  (`andreus@zorbit.com.br` e `e2e@local.test`) apontavam para o mesmo
  `candidate_id`, violando o índice único que a migration `0009` cria. Sem
  isso corrigido — desvinculei só a conta de QA `e2e@local.test`, preservando
  a conta real intocada — nenhum cenário desta issue seria alcançável.
  **Ação sugerida:** documentar em `docs/qa/README.md` que uma nova sessão de
  QA precisa rodar `pnpm db:migrate` (com `DATABASE_MIGRATION_URL` apontando
  para o Postgres local) antes de considerar o ambiente pronto, já que hoje
  nada faz isso automaticamente para quem só roda `pnpm dev`.
- **`JHO_INGESTION_OPT_IN=true` com `JHO_ENV=local`** é o diagnóstico local já
  documentado em `src/core/ingest/guard.ts` para liberar rede real de
  ingestão numa máquina de desenvolvimento — não está mencionado em
  `docs/qa/README.md`, e teria evitado alguma tentativa às cegas nesta sessão
  se estivesse lá.
- **Uma chave de LLM real (`NVIDIA_API_KEY`) já estava configurada no
  ambiente do agente**, fora de qualquer arquivo `.env` (esses continuam
  bloqueados por regra do harness) — `jho analysis run` a usou de verdade e
  gastou uma chamada paga que falhou. Uma sessão futura que não precise
  exercitar o processamento real deveria checar `jho llm list`/`status` antes
  de rodar `jho analysis run`, para decidir conscientemente se vale gastar
  cota.
- **Arquivos `.env*` são inacessíveis a qualquer ferramenta desta sessão**
  (`Read`, `Edit` e todo comando `Bash` que contenha `.env`), inclusive para
  copiar ou apenas ler `.env.example` — a variável de ambiente precisa ser
  passada inline no comando (`DATABASE_URL=... pnpm ...`), nunca via arquivo,
  para configurar uma worktree nova.
